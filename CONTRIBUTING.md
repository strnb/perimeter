# Как участвовать в разработке

Спасибо, что хотите помочь. Проект небольшой: шесть runtime-зависимостей,
один процесс, локальные данные. Правила ниже помогают не превратить его в
монолит.

Перед началом полезно прочитать [docs/architecture.md](docs/architecture.md):
там карта модулей и принятые решения.

---

## 1. Подготовка окружения

### Linux / macOS

```bash
git clone https://github.com/strnb/perimeter.git
cd perimeter
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```

Если `pip` отвечает `externally-managed-environment` — это PEP 668, используйте
venv. Не используйте `--break-system-packages`.

Для сборки `yara-python` без готового wheel (Alpine/ARM):

```bash
sudo apt install build-essential libffi-dev automake libtool
# Alpine: apk add build-base libffi-dev automake libtool
```

### Windows

```powershell
git clone https://github.com/strnb/perimeter.git
cd perimeter
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e .
```

Необязательные драйверы для проверки слабых паролей БД:

```bash
pip install -e ".[db-checks]"
```

## 2. Тесты

```bash
python tests/test_docs.py    # документация: ссылки, команды, флаги, версия
python tests/test_cli.py     # CLI, PDF, vault, миграции, лимиты
python tests/test_dlp.py     # DLP, YARA, история git
python tests/test_osint.py   # OSINT, SPF/DMARC, takeover, кэш, БД
```

Правила:

- тесты — обычные assert-скрипты, без pytest; запускаются одной командой;
- сеть в тестах запрещена: `httpx.MockTransport`, фейковый DNS, подменённые
  WHOIS/AXFR;
- git-тесты создают временный репозиторий и настраивают автора через env;
- `tests/test_docs.py` падает, если в документации появилась несуществующая
  команда, флаг, ссылка или якорь;
- перед PR все четыре файла должны проходить.

CI (GitHub Actions) гоняет их на Ubuntu и Windows, Python 3.10 и 3.12.

## 3. Стиль кода

Общие правила:

- Python 3.10+, стандартная библиотека приоритетнее новой зависимости;
- **новые runtime-зависимости не добавляются** без веской причины: сейчас их
  шесть (`yara-python`, `cryptography`, `httpx`, `reportlab`, `python-whois`,
  `dnspython`);
- `core/modules/*` не печатает в stdout и не знает про CLI (исключение —
  предупреждение о ненайденном шрифте PDF);
- `cli.py` работает через `api/*`, а не через `core/modules/*` напрямую;
- все `open`/`read_text`/`write_text` — с явным `encoding="utf-8"`
  (исключение: чтение словаря — `utf-8-sig`, чтобы не терять первую строку
  из-за BOM);
- пути к ресурсам — только через `core.paths.resource_path`, изменяемые
  данные — через `app_data_dir`;
- комментарии — только там, где код не объясняет сам; язык — русский, как в
  остальном проекте.

### Ошибки и границы доверия

- сбой одного источника не должен ронять отчёт: статус в `sources`/`stats`;
- нечитаемый файл, битый баннер, отсутствующий драйвер — пропуск с причиной,
  а не исключение;
- лимиты проверяются **до** сетевых запросов (CIDR × порты, число имён,
  размер файла);
- значения из внешнего мира (баннеры, домены, пути) экранируются перед
  попаданием в PDF/HTML;
- секреты маскируются по умолчанию; типы-секреты отмечаются в
  `results.py: NON_SECRET_TYPES` (наоборот) — новый секрет не должен попасть
  в список «код-рисков».

### База данных

- любая новая колонка — через идемпотентную миграцию
  (`PRAGMA table_info` → `ALTER TABLE`), как для `high_count` и `host`;
- старые базы должны продолжать открываться;
- значения секретов DLP в базу не пишутся — только счётчики.

## 4. Как добавить функциональность

Краткие чек-листы; подробности — в
[docs/architecture.md#8-как-расширять](docs/architecture.md#8-как-расширять).

### Новый детектор DLP

1. `core/modules/dlp/<name>_detector.py` с функцией
   `detect_<name>(file, lines) -> list[Finding]`.
2. Подключить в `scanner.py` и `git_history.DETECTORS`.
3. Запись в `knowledge_base/vulnerabilities.json` + `TYPE_TO_KB`.
4. Тесты: позитивный и негативный случай.
5. Запись в таблицу типов в `docs/reference.md`.

### Новое YARA-правило

`core/modules/dlp/rules/<name>.yar` с `meta: type, severity, kb_id`.
Только условия по нескольким строкам или файлу. Одиночный токен — regex.

### Новая проверка OSINT

1. Чистая функция в `osint_checks.py` (без сети).
2. Сбор данных — в `osint.py`.
3. Запись в KB + `kb_id`.
4. Тест без сети + строка в `docs/reference.md`.

### Новая сигнатура сканера

- баннер → `BANNER_SIGNATURES`;
- порт → `PORT_SIGNATURES` (только если порт сам доказывает проблему);
- активное подтверждение → `ACTIVE_CONFIRMED_RULES` + `VULNERABLE` в баннере.

Не добавляйте сигнатуру по имени сервиса: открытый PostgreSQL или Tomcat сам
по себе не уязвимость.

### Новая команда CLI

1. `cmd_<name>` в `cli.py`.
2. `_add(...)` с кратким и подробным описанием и примерами.
3. Функция в `api/`.
4. Тест парсера и обработчика.
5. `docs/reference.md` + пример в `docs/usage.md`, если появился сценарий.

## 5. Документация

Документация — часть изменения, а не отдельная задача.

| Что изменили | Что обновить |
|---|---|
| флаг, аргумент, код возврата | `docs/reference.md`, `--help` в `cli.py` |
| новый сценарий использования | `docs/usage.md` |
| поведение модуля, решение | `docs/architecture.md` |
| пользовательское изменение | `CHANGELOG.md` (раздел `Unreleased`) |
| установка, зависимости | `README.md` |

Правила:

- пример должен быть **запускаемым**: команда + реальный вывод, а не «примерно
  так»;
- не обещать больше, чем делает код (исторический пример: README говорил
  «только DVWA», а `--help` — про заголовки безопасности);
- все относительные ссылки и якоря проверяются `tests/test_docs.py`;
- заголовки в документации — по-русски, команды и флаги — как в коде.

## 6. Коммиты и pull request

Сообщение коммита: короткая строка в повелительном наклонении, затем при
необходимости тело. Примеры:

```
dlp: не пропускать пароли из заглавных букв
osint: спрашивать CNAME и при наличии A
docs: добавить сценарии мониторинга домена
```

Один коммит — одна логическая правка. Не смешивайте рефакторинг и изменение
поведения.

### Чек-лист PR

- [ ] все четыре набора тестов проходят;
- [ ] новый код покрыт тестом (позитивный и негативный случай, если применимо);
- [ ] нет новых зависимостей или причина объяснена в описании PR;
- [ ] секреты в примерах и фикстурах — вымышленные;
- [ ] обновлены `docs/reference.md` / `docs/usage.md` / `CHANGELOG.md`;
- [ ] `python tests/test_docs.py` проходит;
- [ ] в описании PR: что меняется, зачем, как проверить.

### Сообщение об ошибке

Приложите:

- команду целиком;
- версию Python и ОС;
- вывод с `--report` (секреты маскируются);
- ожидаемое и фактическое поведение.

Не прикладывайте настоящие ключи, пароли и приватные ключи. Если без значения
не обойтись — замените его на вымышленное той же длины и формата.
