# Периметр CLI

**Терминальный комплекс аудита безопасности**: поиск утечек секретов (DLP, включая историю git), сканирование портов, разведка домена (OSINT), проверки веб-приложения, шифрованное хранилище секретов и PDF-отчёты.

Один бинарник-команда, локальные данные, без сервера и облака.

## Возможности

| Модуль | Что делает | Активность |
|---|---|---|
| **DLP** | Пароли, токены, приватные ключи, строки подключения, хеши паролей, `.netrc`, дампы секретов; SQLi / command injection / слабые сессии в коде | только чтение файлов |
| **DLP · git** | Те же секреты в **истории коммитов** — с автором, датой и хешем коммита | только чтение репозитория |
| **Scan** | TCP-порты, баннеры сервисов, сигнатуры известных уязвимостей, слабые пароли БД (опционально) | сетевое подключение |
| **OSINT** | WHOIS, 9 типов DNS, поддомены из crt.sh и wordlist, SPF/DMARC/DKIM/DNSSEC/CAA | пассивно по умолчанию |
| **OSINT · active** | AXFR, HTTP/TLS-пробы, панели управления, кандидаты на subdomain takeover | активные запросы |
| **Web** | XSS, CSRF, brute force, file upload, open redirect — **профиль DVWA** | активные запросы |
| **Vault** | Шифрованное хранилище секретов: PBKDF2-SHA256 (480 000 итераций) + Fernet | локально |
| **Отчёты** | JSON/TXT по находкам, полный JSON OSINT, сводный PDF по истории из SQLite | локально |

Все находки DLP, сети и веба обогащаются описанием, риском и рекомендацией из
базы знаний (50 записей). Секреты в выводе и отчётах **по умолчанию маскируются**.

## Требования

- **Python 3.10+**
- **git** — только для `dlp --git` (без него остальной DLP работает)
- ОС: Windows 10/11, Linux, macOS
- Для `.[db-checks]`: клиентские библиотеки MySQL / PostgreSQL / MongoDB

Зависимости: `yara-python`, `cryptography`, `httpx`, `reportlab`,
`python-whois`, `dnspython`. Опционально: `pymongo`, `PyMySQL`, `psycopg2-binary`.

## Установка

### Linux / macOS

```bash
git clone https://github.com/strnb/perimeter.git
cd perimeter
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```

Если `pip` отвечает `externally-managed-environment` (Debian 12, Ubuntu 23+),
используйте venv (как выше) — это правильный путь. `--break-system-packages`
не рекомендуется.

Для сборки `yara-python` на Alpine/ARM без готового wheel:

```bash
sudo apt install build-essential libffi-dev automake libtool   # Debian/Ubuntu
# Alpine: apk add build-base libffi-dev automake libtool
```

Проверки слабых паролей БД (необязательно):

```bash
pip install -e ".[db-checks]"
```

### Windows

```powershell
git clone https://github.com/strnb/perimeter.git
cd perimeter
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e .
```

После установки команда `perimeter` доступна из любой директории.

## Быстрый старт

```bash
perimeter                                   # баннер и справка
perimeter dlp ~/project --report            # секреты в файлах + JSON/TXT в ./reports
perimeter dlp . --git                       # + секреты в прошлых коммитах
perimeter scan 192.168.1.10                 # 33 популярных порта + сигнатуры
perimeter osint example.com --report        # WHOIS, DNS, поддомены, находки
perimeter vault save github_token           # пароль и секрет вводятся скрыто
perimeter report -o audit.pdf               # сводный PDF по истории сканов
```

## Команды

Общая справка: `perimeter -h`. Справка по модулю: `perimeter <команда> -h`.

Коды возврата: `0` — успех, `1` — ошибка выполнения, `2` — неверные аргументы
или неизвестная команда, `130` — прервано с клавиатуры.

### dlp — поиск секретов

```bash
perimeter dlp PATH [--report] [--show-secrets] [--git] [--git-depth N]
```

| Флаг | Описание |
|---|---|
| `PATH` | папка для сканирования |
| `--report` | сохранить JSON и TXT в `./reports` |
| `--show-secrets` | печатать и сохранять значения полностью (по умолчанию маскируются) |
| `--git` | проверить историю git: секреты в прошлых коммитах |
| `--git-depth N` | сколько последних коммитов проверять (по умолчанию 1000) |

**Что ищет**

- Пароли и секреты в любом текстовом файле: `password:`, `DB_PASSWORD=`,
  `api_key =`, JSON/YAML/TOML. Заглушки (`${VAR}`, `${{ secrets.X }}`,
  `os.getenv`, `changeme`) не считаются находками.
- Токены: AWS, GitHub (`ghp_`, `github_pat_`), GitLab, OpenAI, Stripe, Slack,
  Google, SendGrid, npm, DigitalOcean, Telegram, JWT.
- Приватные ключи: RSA, DSA, EC, OpenSSH, PKCS#8, encrypted PKCS#8, PGP, PuTTY.
- Строки подключения с паролем: `postgres://user:pass@host`, `mysql://`,
  `mongodb://`, `redis://` и др.
- Файлы хешей паролей (shadow, htpasswd), `.netrc`, дампы из 5+ секретов в файле.
- Код-риски: SQL-инъекции, command injection, предсказуемые идентификаторы сессий.
- Номера строк точные; одинаковые секреты в разных строках — разные находки.

**Что пропускается**

`node_modules`, `venv`, `.git`, `dist`, `build`, `target`, `vendor`, кеши,
lock-файлы, `*.min.js`, `*.map`, двоичные файлы, файлы больше 1 МБ, `.yar`.
В итоговой строке видно, сколько файлов проверено и сколько пропущено.

**История git.** Секрет, удалённый из файла, остаётся в коммитах и доступен
любому, у кого есть клон. `--git` читает `git log --all -p` потоком и смотрит
только добавленные строки. Для каждой находки показывается коммит, где секрет
появился впервые, автор, дата и число коммитов с ним. Если секрет до сих пор
лежит в файле, запись не дублируется — к ней добавляются данные из истории.

> Удаления файла недостаточно: секрет нужно **ротировать** (сменить ключ или
> пароль), затем вычистить историю (`git filter-repo`) и уведомить всех, у кого
> уже есть клон.

### scan — порты и сигнатуры

```bash
perimeter scan TARGET [--ports PORTS] [--report]
```

| Аргумент | Описание |
|---|---|
| `TARGET` | IP, домен или CIDR-подсеть |
| `--ports` | `22,80,8000-8100`; по умолчанию 33 популярных порта |
| `--report` | JSON/TXT в `./reports` |

- Баннеры читаются для открытых портов, сервис определяется по порту и ответу.
- Сигнатуры срабатывают по содержимому баннера; «открытый PostgreSQL» сам по
  себе не считается уязвимостью.
- Слабые пароли MySQL/PostgreSQL/MongoDB проверяются только с `.[db-checks]`;
  без драйверов в баннере честно пишется «проверка недоступна».
- Защита от опечатки: больше 65 536 проверок (хосты × порты) — отказ до
  отправки первого пакета.
- Параллелизм — 100 задач; подробности по каждому порту сохраняются в историю
  вместе с хостом.

### osint — разведка домена

```bash
perimeter osint DOMAIN [--active] [--sources LIST] [--concurrency N]
                        [--wordlist PATH] [--no-cache] [--json PATH] [--report]
```

| Флаг | Описание |
|---|---|
| `--active` | AXFR, HTTP/TLS-пробы поддоменов, панели, takeover |
| `--sources` | `crt,wordlist,hackertarget` (по умолчанию `crt,wordlist`) |
| `--concurrency` | параллельных DNS-запросов (по умолчанию 50) |
| `--wordlist` | свой список поддоменов |
| `--no-cache` | игнорировать кэш (TTL 24 ч) |
| `--json` | полный отчёт в указанный файл |
| `--report` | полный JSON в `./reports` |

**Пассивный режим (по умолчанию)**

- WHOIS: регистратор, организация, даты создания и истечения, возраст,
  статусы, NS. Срок домена ≤ 60 дней — находка.
- DNS: `A, AAAA, MX, TXT, NS, SOA, CNAME, CAA, DS` — все адреса, а не первый.
- Поддомены: crt.sh (Certificate Transparency) + wordlist. Wildcard DNS
  определяется двумя случайными именами и фильтруется по множеству IP.
- Почта: SPF (`+all`, `?all`, нет `all`, несколько записей, >10 lookup),
  DMARC (`none`, нет политики), DKIM по частым селекторам.
- DNSSEC и CAA.
- Кэш 24 часа в `~/.perimeter/cache/osint/`; повторный запуск почти мгновенный.
- Сравнение с прошлым сканом: «новых с прошлого скана: N».

**Активный режим (`--active`)**

- AXFR по каждому NS — если зона отдалась, это critical.
- HTTP-проба поддоменов: статус, `Server`, `<title>`, срок TLS-сертификата.
  Тело читается потоком и обрезается на 200 КБ.
- Панели управления по заголовку (Jenkins, Grafana, phpMyAdmin, Kibana и др.).
- Кандидаты на subdomain takeover: CNAME на известный сервис + ответ
  «приложения не существует». Формулировка всегда «кандидат, проверить вручную».

**Свой словарь поддоменов.** Встроенный список — 2 274 имени. SecLists
подхватывается автоматически, если установлен в стандартное место
(`/usr/share/seclists`, `/usr/share/wordlists/seclists`, `/opt/...`, Homebrew):

```bash
sudo apt install seclists      # Debian/Ubuntu/Kali
brew install seclists          # macOS

perimeter osint example.com --wordlist ~/seclists/Discovery/DNS/dns-Jhaddix.txt
export PERIMETER_WORDLIST=~/seclists/Discovery/DNS/subdomains-top1million-5000.txt
```

5 000 имён — разумный компромисс: встроенный список на домашнем резолвере
занимает несколько десятков секунд, а crt.sh часто даёт больше покрытия,
чем перебор.

### web — веб-проверки

```bash
perimeter web TARGET [--port PORT] [--cookie K=V] [--report]
```

| Флаг | Описание |
|---|---|
| `TARGET` | IP или хост |
| `--port` | порт приложения, по умолчанию 4280 |
| `--cookie` | cookie сессии, можно несколько раз |
| `--report` | JSON/TXT в `./reports` |

Проверки: brute force / отсутствие rate limiting, CSRF, reflected XSS,
unrestricted file upload, open redirect.

> **Важно:** профиль проверок настроен на пути **DVWA**
> (`/vulnerabilities/...`). На обычном приложении проверки получат 404 и
> покажут «находок 0». Модуль предназначен для учебного стенда DVWA, а не для
> аудита произвольного сайта. File upload оставляет тестовый файл на стенде —
> это помечено в коде как `shortcut:`.

### pipeline — домен и его хосты

```bash
perimeter pipeline DOMAIN [--scan] [--ports PORTS] [--concurrency N] [--json PATH]
```

По умолчанию выполняет только OSINT и печатает сводку. С `--scan` дополнительно
сканирует порты всех найденных хостов и обогащает находки.

> IP за Cloudflare/CDN принадлежат провайдеру, а не владельцу домена. Поэтому
> скан портов выключен по умолчанию: запускайте `--scan` только для своей
> инфраструктуры.

`--concurrency` — сколько хостов сканировать одновременно (по умолчанию 10).

### vault — хранилище секретов

```bash
perimeter vault save NAME     # мастер-пароль и секрет вводятся скрыто
perimeter vault load NAME     # печатает значение в stdout
perimeter vault list          # имена без пароля
```

- Ключ: PBKDF2-HMAC-SHA256, 480 000 итераций, случайная соль.
- Шифрование: Fernet (AES-128-CBC + HMAC).
- Мастер-пароль хранится как солёный PBKDF2-хеш, сравнение — `compare_digest`.
- Запись атомарная (`os.replace`), на POSIX файлы `0600`, каталог `0700`.
- Старые vault с несолёным SHA-256 автоматически переводятся на новый формат
  при первом успешном входе.

### report / history / clear

```bash
perimeter report [-o FILE]     # PDF по истории из БД (по умолчанию perimeter_report.pdf)
perimeter history [--limit N]  # последние записи DLP / NETWORK / OSINT (по умолчанию 5)
perimeter clear [--yes]        # удалить всю историю
```

PDF содержит сводку, последние сканы OSINT, DLP и сетевые детали по портам.
Для DLP в PDF выводятся только счётчики — сами секреты в базу не пишутся.
Все значения из БД экранируются, поэтому `<`, `>`, `&` в баннерах отчёт не ломают.

### completion — автодополнение

```bash
# bash — в ~/.bashrc
eval "$(perimeter completion bash)"

# zsh — в ~/.zshrc
eval "$(perimeter completion zsh)"

# PowerShell 7+ — в $PROFILE
perimeter completion powershell | Add-Content $PROFILE
```

Tab предлагает команды, действия vault и флаги модулей, не ломая обычное
дополнение путей. PowerShell 5.1 не поддерживается (нет
`Register-ArgumentCompleter -Native`) — обновитесь до 7+ или включите
подсказки по истории: `Set-PSReadLineOption -PredictionSource History`.

## Где хранятся данные

| Что | Репозиторий / `pip install -e .` | Обычный `pip install .` |
|---|---|---|
| История сканов | `./perimeter.db` | `~/.perimeter/perimeter.db` |
| Vault | `./vault/` | `~/.perimeter/vault/` |
| Кэш OSINT | `~/.perimeter/cache/osint/` | `~/.perimeter/cache/osint/` |
| Отчёты `--report` | `./reports/` (текущая директория) | то же |
| PDF `report -o` | указанный путь | то же |

В `perimeter.db` хранятся: время, цель, счётчики находок, баннеры и заголовки
уязвимостей, поддомены и их IP. **Значения секретов DLP в базу не пишутся.**
Сама база не шифруется — это локальный файл, доступ к нему определяется правами
ОС. Vault шифрует значения секретов, но имена хранит открыто.

## Ограничения и лимиты

| Ограничение | Значение | Как обойти |
|---|---|---|
| Размер файла DLP | 1 МБ | разбить файл или сканировать по частям |
| Глубина истории git | 1 000 коммитов | `--git-depth N` |
| Находок из истории | 500 | сузить путь или глубину |
| Проверок в скане портов | 65 536 (хосты × порты) | сузить CIDR или список портов |
| Имён поддоменов | 20 000 | `--wordlist` с меньшим списком |
| Имён из crt.sh | 5 000 | — |
| HTTP-проб за `--active` | 200 | — |
| Тело HTTP-пробы | 200 КБ | — |
| Кэш OSINT | 24 ч | `--no-cache` |
| Параллелизм DNS | 50 | `--concurrency N` |
| Параллелизм портов | 100 | — |

Известные особенности:

- **Web-модуль — только DVWA.** Проверки ходят по путям `/vulnerabilities/...`;
  на реальных приложениях они получают 404 и дают «находок 0».
- **DLP смотрит только добавленные строки истории**, а не удалённые: секрет,
  который когда-то был в файле, всё равно был добавлен в каком-то коммите.
- **YARA необязательна.** Если правила не скомпилировались, DLP работает на
  regex-детекторах и предупреждает об этом.
- **Subdomain takeover — только кандидат.** Автоматическое подтверждение
  требует ручной проверки, ложные critical исключены намеренно.
- **hackertarget** — бесплатный API с лимитом около 100 запросов в сутки,
  включается вручную через `--sources`.
- **Сканер портов не делает host discovery** — на подсети за файрволом
  время ожидания растёт пропорционально числу хостов.

## Устройство проекта

```
perimeter-cli/
├── cli.py                     # argparse, команды, вывод, автодополнение
├── database.py                # SQLite: схема, миграции, запись результатов
├── api/                       # фасад модулей (import api; api.scan_dlp(...))
│   ├── dlp.py  network.py  osint.py  web.py  pipeline.py
│   ├── vault.py  knowledge.py  reports.py  paths.py
├── core/
│   ├── paths.py               # пути к ресурсам и к ~/.perimeter
│   └── modules/
│       ├── dlp/               # детекторы, YARA-правила, git-история
│       ├── scanner/           # порты, баннеры, сигнатуры, OSINT, проверки
│       ├── web_scanner/       # 5 проверок DVWA
│       ├── vault/             # PBKDF2 + Fernet, атомарная запись
│       └── report_generator_utils/  # PDF (reportlab, DejaVuSans)
├── knowledge_base/            # 50 записей: описание, риск, рекомендация
├── assets/                    # DejaVuSans.ttf для кириллицы в PDF
├── tests/                     # 3 набора assert-тестов, без pytest
├── pyproject.toml
├── LICENSE                    # MIT
└── README.md
```

Принципы:

- **api/** только реэкспортирует функции модулей — CLI не знает внутренностей.
- **Данные отдельно от кода**: ресурсы ищутся в репозитории или в
  `<prefix>/share/perimeter`; изменяемые данные лежат рядом с кодом в
  editable-режиме и в `~/.perimeter` после обычной установки.
- **Сетевые модули не падают целиком** из-за одного источника: сбой попадает
  в отчёт как статус (`crt.sh: HTTP 502`), остальное собирается.
- **Один детектор — один владелец**: YARA отвечает только за файловые условия,
  которые не выразить одной строкой; regex-детекторы — за одиночные секреты.

## Тесты

Тесты не требуют pytest и сети — это assert-скрипты:

```bash
python tests/test_cli.py     # CLI, сигнатуры и лимиты скана, PDF, vault, миграции БД
python tests/test_dlp.py     # DLP, YARA, история git, ложные срабатывания
python tests/test_osint.py   # OSINT: домены, SPF/DMARC, takeover, кэш, БД
```

Что покрыто:

- DLP: 13 позитивных сценариев (YAML/JSON/Python/.env, UTF-16, PKCS#8,
  connection string, shadow, AWS, все токены) и негативные (`task-`/`risk-`,
  `${{ secrets.X }}`, `os.getenv`, lock-файлы, `dist/`, бинарники, >1 МБ).
- Git: настоящий временный репозиторий с 6 коммитами — поиск удалённого
  секрета, автор/дата, число коммитов, подпапка, глубина, отсутствие дублей.
- OSINT: нормализация домена и IDN, матрица SPF/DMARC, AXFR, wildcard DNS,
  takeover, кэш, миграция схемы, CLI и diff с прошлым сканом.
- PDF: генерируется на реальных данных из БД, включая значения с `<`, `>`, `&`;
  проверяется миграция `network_details`.

Живые проверки (сеть, DVWA) в тесты не входят — они требуют разрешения владельца.

## Решение проблем

| Симптом | Причина и решение |
|---|---|
| `externally-managed-environment` | PEP 668: используйте venv (`python3 -m venv .venv`) |
| `yara-python` не собирается | нужны `build-essential libffi-dev automake libtool` (Alpine: `build-base libffi-dev`) |
| `История git не проверена: git не установлен` | установите git или запустите без `--git` |
| `[!] YARA-правила недоступны` | DLP продолжает работать на regex; проверьте установку `yara-python` |
| Кириллица в PDF — квадраты | не найден `assets/DejaVuSans.ttf`; при `pip install .` проверьте `share/perimeter/assets` |
| `Слишком большой объём скана` | сузьте CIDR или список портов (лимит 65 536 проверок) |
| crt.sh отвечает 502 | модуль сам повторяет запрос; при недоступности используйте `--sources wordlist` |
| Tab не работает в PowerShell 5.1 | обновитесь до PowerShell 7+ |
| `Неизвестная команда` | CLI подсказывает ближайшую команду; полный список — `perimeter -h` |
| Пустой отчёт на реальном сайте | `web` работает только по путям DVWA |

Диагностика сетевых модулей идёт через `logging`; CLI показывает только
итоговые сообщения и ошибки.

## Безопасность

- **Секреты маскируются по умолчанию** и в консоли, и в отчётах. Полные
  значения выводятся только с `--show-secrets` — такой файл считается
  конфиденциальным.
- **Vault** хранит мастер-пароль как солёный PBKDF2-хеш (480 000 итераций),
  данные шифруются Fernet; запись атомарная, на POSIX права `0600`.
- **В историю попадают только счётчики DLP**, не сами секреты.
- **Активные действия** (`--active`, `web`, `pipeline --scan`, file upload) видны в
  логах целевой системы. Запускайте их только с разрешения.
- **Юридически:** инструмент не даёт права сканировать чужие ресурсы.
  Ответственность за использование лежит на операторе.

## Участие в разработке

1. Форкните репозиторий и создайте ветку: `git switch -c feature/имя`.
2. Установите в venv: `pip install -e .`.
3. Перед PR прогоните все три набора тестов — они должны быть зелёными.
4. Новые зависимости не добавляйте без необходимости: проект сознательно
   обходится шестью пакетами.
5. Для новых находок добавляйте запись в `knowledge_base/vulnerabilities.json`
   (id, title, severity, description, risk, fix) и указывайте `kb_id`.
6. Для нового сетевого кода — изолируйте сбой источника: ошибка должна
   попадать в отчёт, а не ронять команду.
7. Секреты в тестах — только вымышленные; настоящие ключи в фикстурах
   запрещены.

Сообщения об ошибках: приложите команду, версию Python, ОС и вывод
с `--report` (секреты маскируются).
