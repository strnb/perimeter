# Сценарии использования

Практические задачи. В каждом разделе: цель, команда, реальный вывод,
что делать дальше. Полный список флагов — в [reference.md](reference.md).

Все команды выполняются для **своей** инфраструктуры или по договору.
Активные проверки помечены предупреждением.

---

## 1. Проверить, что установка работает

```bash
perimeter -h
```

Ожидаемо: баннер, список команд, код возврата `0`.

```bash
perimeter dlp . 
```

Первый запуск создаёт `perimeter.db` рядом с проектом (или `~/.perimeter/`
после обычной установки) и пишет туда счётчики.

Если `perimeter` не найдена — активируйте venv или используйте
`python -m cli` из папки проекта.

---

## 2. Проверить проект на секреты

Цель: найти ключи и пароли в рабочем дереве до того, как они уедут в репозиторий.

```bash
perimeter dlp ~/work/myproject --report
```

Реальный вывод на тестовой `.env`:

```
[CRITICAL] aws_key              /home/user/project/.env:2
           AKIA…
           fix: Немедленно отозвать обнаруженный токен, выпустить новый и хранить секреты вне исходного кода.
[CRITICAL] connection_string    /home/user/project/.env:3
           …
           fix: Сменить пароль, вынести его в переменные окружения или vault, убрать строку из репозитория и истории git.
[HIGH    ] password             /home/user/project/.env:1
           Prod…
           fix: Перенести секреты в переменные окружения или систему управления секретами и заменить скомпрометированные пароли.

Итого: критических 2, высоких 1, средних 0, низких 0
Проверено файлов: 1
```

Что происходит:

- значения **маскируются**: первые 4 символа и `…`; короче 9 символов — только `…`;
- каждая находка обогащена описанием, риском и рекомендацией из базы знаний;
- отчёт `--report` кладёт JSON и TXT в `./reports/`;
- в базу пишутся только счётчики, не сами секреты.

Полные значения нужны для ротации — только тогда:

```bash
perimeter dlp ~/work/myproject --show-secrets
```

Файл с таким выводом считайте секретным.

**Что считается находкой:** см. таблицу типов в
[reference.md#типы-находок-dlp](reference.md#типы-находок-dlp).

**Что пропускается:** `node_modules`, `venv`, `.git`, `dist`, `build`,
`target`, `vendor`, lock-файлы, `*.min.js`, двоичные файлы, файлы больше 1 МБ.

Если в итоге много ложных срабатываний на вашем проекте — добавьте пути в
`EXCLUDED_DIRS` / `EXCLUDED_FILENAMES` в `core/modules/dlp/scanner.py`
(см. [architecture.md#добавить-исключение-для-dlp](architecture.md#добавить-исключение-для-dlp)).

## 3. Найти секреты, которые уже попали в историю

Цель: ключ удалили из файла, но он остался в коммитах и доступен каждому,
у кого есть клон.

```bash
perimeter dlp . --git
```

Реальный вывод (фрагмент):

```
[HIGH    ] password             config/old.env:3
           DB_P…
           git 4f2c1a9 2025-11-02 добавил конфиг
           удалён из кода; коммитов с этим секретом: 3
```

Поля:

- `git <хеш> <дата> <тема>` — коммит, где секрет появился **впервые**;
- `коммитов с этим секретом` — сколько всего коммитов его содержит;
- `удалён из кода` — в рабочем дереве секрета уже нет;
- `сейчас в файле, но есть и в истории` — секрет всё ещё лежит в файле.

Настройки:

```bash
perimeter dlp . --git --git-depth 5000    # глубже, чем 1000 коммитов по умолчанию
perimeter dlp . --git --report            # JSON/TXT с полями commit/date/subject/commits
```

**Удалить файл недостаточно.** Порядок действий:

1. Ротировать секрет: сменить пароль, отозвать ключ, перевыпустить токен.
2. Вычистить историю: `git filter-repo --path config/old.env --invert-paths`
   (или BFG), затем force-push.
3. Предупредить всех, у кого уже есть клон: старый коммит остаётся у них.

Если git не установлен или папка не репозиторий, остальной DLP работает, а в
итоге появится строка `[!] История git не проверена: …`.

Ограничения: читаются только **добавленные** строки, не более 1000 коммитов по
умолчанию, не более 500 находок из истории. Submodules и LFS не разбираются.

## 4. Понять находку и что с ней делать

Каждая находка содержит `fix` из `knowledge_base/vulnerabilities.json`.
Читать её в контексте:

```bash
perimeter dlp . --report
cat reports/scan_*.txt | head -50
```

Для программной обработки:

```bash
jq -r '.findings[] | "\(.severity)\t\(.type)\t\(.file):\(.line)"' reports/scan_*.json
```

Порядок:

1. `critical` — ротировать немедленно, до любых других действий.
2. `high` — ротировать в тот же день.
3. Проверить, не утёк ли секрет наружу (логи CI, публичные форки).
4. Добавить в `.gitignore`, перенести в vault или переменные окружения.
5. Включить `perimeter dlp . --git` в pre-push или CI.

## 5. Проверить один хост

Цель: какие порты открыты и что за сервисы.

```bash
perimeter scan 192.168.1.10
```

Вывод: таблица открытых портов, сервис, баннер, сигнатуры уязвимостей.
Итог пишется в историю (`network_results` + `network_details` с хостом).

Свой список портов:

```bash
perimeter scan 192.168.1.10 --ports 22,80,443,8000-8100
```

По умолчанию проверяются 33 популярных порта. Разбор:

- сигнатура срабатывает по **баннеру**, а не по имени сервиса: `vsftpd 2.3.4`,
  `Samba 3.0`, `distccd`, `UnrealIRCd`;
- открытый PostgreSQL **не** считается уязвимым сам по себе;
- слабые пароли MySQL/PostgreSQL/MongoDB проверяются только с
  `pip install -e ".[db-checks]"`; без драйверов в баннере честно написано
  `проверка слабых паролей недоступна`;
- SMB показывает `SMB Negotiate: …` — это подтверждение протокола, а не
  уязвимость.

## 6. Просканировать подсеть

```bash
perimeter scan 10.0.0.0/24 --report
```

Что важно знать:

- лимит — 65 536 проверок (`хосты × порты`). `/24` × 33 порта = 8 448 — норма;
  `/8` будет отклонён до отправки первого пакета;
- сканер не делает host discovery: хосты за файрволом просто не ответят;
- результат по подсети в `history` и PDF показывает хост у каждого порта.

Пример расчёта: `/24` и диапазон `1-1000` = 254 × 1000 = 254 000 — больше
лимита, команда попросит сузить диапазон.

## 7. Разведка домена без активных действий

Цель: WHOIS, DNS, поддомены, почтовая конфигурация — не касаясь серверов.

```bash
perimeter osint example.com
```

Реальный вывод (сокращён):

```

Источники: whois ok | dns ok | crt.sh crt.sh: 5 | wordlist отключён

WHOIS
  Регистратор : RESERVED-Internet Assigned Numbers Authority
  Создан      : 1995-08-14 (11428 дн.)
  Истекает    : 2027-08-13 (через 258 дн.)
  NS          : elliott.ns.cloudflare.com, hera.ns.cloudflare.com

DNS
  A    : 8.47.69.1, 8.6.112.1
  MX   : 0 .
  TXT  : v=spf1 -all, _k2n1y4vw3qtb4skdx9e7dxt97qrmmq9
  DS   : 2371 13 2 c988ec423e3880eb8dd8a46fe06ca230ee23f35b578d64e78b29c3e1c83d245a
  DNSSEC: да

ПОЧТА
  SPF  : v=spf1 -all  (lookup: 0)
  DMARC: reject
  DKIM : —

ПОДДОМЕНЫ (1; crt.sh/пассивные 1, wordlist 0)
  новых с прошлого скана: нет
  www.example.com

НАХОДКИ: 1
  [LOW     ] CAA не настроен
             Любой удостоверяющий центр может выпустить сертификат на домен.
             fix: Добавить CAA-запись, разрешающую выпуск только вашему CA.
```

Время зависит от crt.sh (он отвечает медленно) и DNS. Второй запуск в течение
24 часов берётся из кэша почти мгновенно.

Источники поддоменов:

```bash
perimeter osint example.com --sources crt,wordlist
perimeter osint example.com --sources crt,wordlist,hackertarget
perimeter osint example.com --wordlist ~/seclists/Discovery/DNS/dns-Jhaddix.txt
export PERIMETER_WORDLIST=~/seclists/Discovery/DNS/subdomains-top1million-5000.txt
```

SecLists подхватывается автоматически из стандартных путей. Встроенный
словарь — 2 274 имени.

Полный JSON:

```bash
perimeter osint example.com --json osint.json
jq -r '.findings[] | "\(.severity) \(.type)"' osint.json
jq -r '.subdomains[] | "\(.subdomain) \(.ips|join(","))"' osint.json
```

Что означают находки — [reference.md#находки-osint](reference.md#находки-osint).

## 8. Активная проверка домена

> Запускайте только для своих систем или по договору. Проверки видны в логах
> целевой стороны.

```bash
perimeter osint example.com --active --report
```

Добавляет:

- AXFR по каждому NS (5 с таймаут) — если зона отдалась, это `critical`;
- HTTP-пробу поддоменов: статус, `Server`, `<title>`, срок TLS;
- поиск панелей управления по заголовку (Jenkins, Grafana, phpMyAdmin, Kibana);
- кандидатов на subdomain takeover: CNAME на известный сервис + ответ
  «приложения не существует».

Ограничения:

- HTTP-проба — не более 200 имён за запуск (при большем числе в лог пишется
  предупреждение);
- тело ответа читается до 200 КБ;
- takeover — всегда **кандидат**, подтверждать вручную: занять имя у провайдера
  может только владелец аккаунта.

## 9. Следить за доменом регулярно

Цель: узнавать о новых поддоменах, истечении домена и сертификатов.

Ежедневный запуск (cron, Linux):

```cron
0 6 * * * cd /opt/perimeter && .venv/bin/perimeter osint example.com --no-cache --report >> /var/log/perimeter-osint.log 2>&1
```

`--no-cache` обязателен: кэш живёт 24 часа, и запуск ровно через сутки может
взять устаревшие данные.

Что смотреть в выводе:

```
ПОДДОМЕНЫ (47; crt.sh/пассивные 41, wordlist 6)
  новых с прошлого скана: 3 — dev.example.com, old.example.com, vpn.example.com
```

Сравнение идёт с последним **сохранённым** сканом этого домена. Запуски из кэша
в историю не пишутся, поэтому не создают ложных «изменений».

Windows Task Scheduler: то же самое, `perimeter.exe osint example.com --no-cache`.

## 10. Собрать PDF для заказчика

```bash
perimeter report -o audit.pdf
```

PDF строится по истории из `perimeter.db`: сводка, последние сканы OSINT
(поддомены, находки, срок домена), DLP (критические / высокие / средние /
низкие) и сетевые детали по портам с хостом.

Для отчёта нужна история, поэтому сначала выполните нужные команды с
сохранением — они пишут в БД автоматически: `dlp`, `scan`, `osint`.

Проверка перед отправкой:

- кириллица отображается (шрифт `assets/DejaVuSans.ttf` входит в пакет);
- в PDF нет значений секретов — DLP пишет только счётчики;
- данные актуальны: `perimeter history --limit 10`.

## 11. Хранить секреты в vault

```bash
perimeter vault save github_token     # мастер-пароль и значение — скрыто
perimeter vault list                  # имена, без пароля
perimeter vault load github_token     # печатает значение в stdout
```

Криптография: PBKDF2-HMAC-SHA256, 480 000 итераций, случайная соль; шифрование
Fernet (AES-128-CBC + HMAC). Мастер-пароль хранится солёным хешем.

Файлы vault: `.master`, `.salt`, `encrypted.json`. **Резервная копия — все три.**
Без `.salt` секреты не расшифровать: инструмент скажет об этом прямо и не будет
создавать новый ключ.

На POSIX файлы создаются с правами `0600`, каталог — `0700`.

Что vault не умеет: удалять и переименовывать секреты (только save/load/list),
работать без интерактивного ввода пароля.

## 12. Отдать результат в другой инструмент

| Команда | Формат | Где |
|---|---|---|
| `dlp … --report` | JSON + TXT | `./reports/scan_<дата>_<время>.json/.txt` |
| `scan … --report` | JSON + TXT | то же |
| `web … --report` | JSON + TXT | то же |
| `osint … --json PATH` | JSON | указанный путь |
| `osint … --report` | JSON | `./reports/osint_<домен>_<дата>.json` |
| `pipeline … --json PATH` | JSON | указанный путь |

Примеры `jq`:

```bash
# только критичные находки DLP
jq -r '.findings[] | select(.severity=="critical") | .file' reports/scan_*.json

# секреты из истории git
jq -r '.findings[] | select(.commit) | "\(.commit) \(.file) \(.type)"' reports/scan_*.json

# поддомены, которые отвечают по HTTPS
jq -r '.subdomains[] | select(.http.status) | .subdomain' reports/osint_*.json
```

## 13. Включить автодополнение

```bash
# bash — в ~/.bashrc
eval "$(perimeter completion bash)"

# zsh — в ~/.zshrc
eval "$(perimeter completion zsh)"

# PowerShell 7+ — в $PROFILE
perimeter completion powershell | Add-Content $PROFILE
```

Tab предлагает команды, действия vault и флаги текущего модуля, не ломая
дополнение путей. Fish и PowerShell 5.1 не поддерживаются.

## 14. Частые ошибки

| Сообщение | Причина | Решение |
|---|---|---|
| `Неизвестная команда 'dpl'. Возможно: dlp.` | опечатка | исправьте команду, `perimeter -h` |
| `Путь не найден или это не папка` | неверный путь в `dlp` | проверьте путь |
| `Слишком большой объём скана` | `хосты × порты > 65 536` | сузьте CIDR или порты |
| `это не домен: …` | в `osint` передан URL без домена/мусор | передайте `example.com` |
| `[!] YARA-правила недоступны` | `yara-python` не установлен | `pip install yara-python`; DLP продолжит работать на regex |
| `[!] История git не проверена: git не установлен` | нет git в PATH | установите git или запускайте без `--git` |
| `Потерян файл .salt…` | удалён `.salt` | восстановите из бэкапа; новый salt не поможет |
| `Секрет 'x' не найден` | имени нет в vault | `perimeter vault list` |
| `externally-managed-environment` | PEP 668 | используйте venv |
| PDF с квадратами вместо кириллицы | не найден шрифт | проверьте `assets/DejaVuSans.ttf` / `share/perimeter/assets` |

Полный список кодов возврата — [reference.md#коды-возврата](reference.md#коды-возврата).
