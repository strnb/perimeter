# Документация «Периметр CLI»

Документация разложена по слоям: у каждого своя аудитория и задача. Начните с
того, что вам нужно прямо сейчас.

| Если вы хотите… | Читайте |
|---|---|
| Понять, что это за инструмент и установить его | [README](../README.md) |
| Сделать конкретную задачу: проверить проект, подсеть, домен | [usage.md](usage.md) |
| Найти точный флаг, код ошибки, лимит, формат отчёта | [reference.md](reference.md) |
| Понять, как устроен код и как его расширять | [architecture.md](architecture.md) |
| Собрать, протестировать и прислать PR | [CONTRIBUTING.md](../CONTRIBUTING.md) |
| Узнать, что изменилось между версиями | [CHANGELOG.md](../CHANGELOG.md) |
| Получить справку по команде | `perimeter <команда> -h` |

## Принципы

1. **Один раздел — один сценарий.** «Как просканировать подсеть», а не
   «описание модуля scan».
2. **Примеры запускаемые.** Команды и вывод в документации взяты из реального
   запуска, а не придуманы. Если пример устарел — это баг (см. `tests/test_docs.py`).
3. **Один источник правды.** Флаги и их описания генерируются из `cli.py`:
   справочник ниже сверяется с `perimeter -h` автоматически. При расхождении
   падает тест документации.
4. **Ограничения написаны явно.** Что не поддерживается, какие лимиты, какие
   данные меняются — это экономит больше вопросов, чем любой туториал.
5. **Документация в том же PR, что и код.** Изменили флаг — обновите
   `reference.md` в том же коммите.

## Карта репозитория

```
README.md               что это, установка, быстрый старт
docs/
  README.md             эта страница: навигация
  usage.md              сценарии «хочу сделать X»

CONTRIBUTING.md         как собрать, тесты, стиль, PR

```

## Проверка документации

```bash
python tests/test_docs.py
```

Скрипт проверяет:

- все относительные ссылки и якоря ведут на существующие файлы и заголовки;
- каждая команда `perimeter …` в примерах — реальная подкоманда;
- каждый длинный флаг в примерах (`--git`, `--active`, `--json`, …) существует
  в `argparse`;
- `CHANGELOG.md` содержит текущую версию из `pyproject.toml`.

Тот же скрипт запускается в CI на каждый push и pull request.
